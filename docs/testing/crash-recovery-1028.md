# Crash recovery evidence and remaining work

This branch implements the first R4 durability and recovery slices from the crash audit at `81cc8bd353456c17b1cb136a217a92f8f32285af`. It does **not** establish that every crash needs no human intervention. G04 and G08 remain open, and the native sandbox, macOS, Windows, and power-loss qualification below is still required.

The coordinator keeps its existing SQLite transactions. Local replacements share `lib/durable-write.mjs`: private exclusive temporary file, complete write, file sync, rename, directory sync, and ancestor-directory sync. Unsupported or failed sync returns an error. The asynchronous entrypoint preserves app control-request scheduling. Existing append logs and telemetry stores have not all been migrated; this is not a claim that every file in the repository is power-loss durable.

The attempt counter store owns the output spool, completion intent, and cessation intent. Collected bytes and receipt inputs commit before sandbox teardown. A completion acknowledgement clears the spool; an explicit rejection moves it to a private retained record before clearing its active obligation. Recovery uses saved identities and exact completion payloads, without extending leases or launching an agent. Paused and Off app startup run that recovery even without installed adapters.

## Evidence by finding

The process harness waits for an IPC boundary, sends SIGKILL from the parent, waits for process death, and starts a fresh process. The main result and outbox scenarios use a real HTTP coordinator and SQLite store. Sandbox execution is a deterministic fake backend; no provider calls occur.

Run the crash scenarios with `nice -n 10 node --test tests/v1-crash-*.test.mjs`. `nice -n 10 npm test` and `nice -n 10 npm run test:ui` exercise the broader regressions. Full-run and failed-run logs remain under `~/.tmp/fix-1028/g-*.log`; the first full Node run's per-file logs are retained in `~/.tmp/fix-1028/g-node-run-1-files`.

The original G12 test used a 250 ms real-clock deadline and could pass with the recurring reaper removed because startup ran after expiry. Its original passing result is not evidence for recurring recovery. The replacement keeps time fixed across SIGKILL and restart, records the startup inventory before advancing time, and fails on the abandoned diagnostic's continued presence when the pre-G12 module is loaded. The corrected crash test and five related journal/provisioning checks pass; no production reaper change was needed in this review round.

## Remaining acceptance work

- G04 needs a cooperating execution owner with durable launch and result status. A host-side retry would risk a second execution.
- G08 needs installed macOS, Linux desktop, and non-systemd coordinator restart tests, including explicit Quit and one active owner. This branch restarts through `startApp`, not through a killed native supervisor.
- G01 needs real VM power cuts and filesystem qualification, including first install. SIGKILL keeps the kernel page cache alive; the filesystem model is evidence about ordering only. Directory-sync support on Windows and macOS has not been qualified.
- G02 needs real sbx crashes during collection, verification, between artifact uploads, and under disk failure, plus bounded-spool and cleanup-debt stress. The pre-seal collection window is not closed by the tested spool protocol.
- G06 needs source/roster-change crash cases and prolonged-outage stress beyond the bounded fairness test.
- G09 needs native process identity and tray coverage. G12 needs the normal installed app and real diagnostic sandboxes.

No files or directories created for this task were manually deleted. The clone, dependencies, test artifacts, baseline loader, scripts, and failed logs remain for review. No merge was performed.
